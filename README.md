# 泌尿科 繼續教育活動彙整

[![更新活動資料](https://github.com/platypus31/taiwan-urology-cme/actions/workflows/update.yml/badge.svg)](https://github.com/platypus31/taiwan-urology-cme/actions/workflows/update.yml)
[![CI](https://github.com/platypus31/taiwan-urology-cme/actions/workflows/ci.yml/badge.svg)](https://github.com/platypus31/taiwan-urology-cme/actions/workflows/ci.yml)

把台灣泌尿科相關學會公告的活動抓下來，變成一頁可以用**時間／地區／積分／主題／主辦／來源**篩選的清單。
純靜態網站，資料存成一份 JSON，靠 GitHub Actions 每天自動更新，沒有伺服器也沒有資料庫。

> 資料只是彙整索引，**報名與積分認定一律以主辦單位公告為準**。

## 兩個分頁：積分課程 vs 學會會議

站上有兩份互不相干的清單，用頁面上方的分頁切換。分開的理由是**它們回答的問題不一樣**：

| 分頁 | 給誰 | 回答什麼 | 資料來源 | 過期的怎麼處理 |
|------|-----|---------|---------|--------------|
| **積分課程**（`kind: cme`） | 住院醫師 | 這段時間有哪些課可以拿泌尿科積分 | 台灣泌尿科醫學會 E-School 會議列表 | 過期就從站上消失（`KEEP_PAST_DAYS = 0`） |
| **學會會議**（`kind: meeting`） | 主治醫師 | 這幾個學會什麼時候開會 | TUA 自己的年會／半年會＋TEA／TUOA 官網＋高杏（見下表） | **保留兩年份**（`MEETING_KEEP_PAST_DAYS = 730`）＊ |

＊ 高杏是例外，**實際上只有約 12 個月的歷史**：它的資料是一個月一個請求地從 E-School
翻出來的（`kaohsing.MONTHS_BACK = 12`），掃到 24 個月等於每天多打 12 個請求到別人的網站，
為一個一年辦一兩場的地方協會不划算。TEA／TUOA 一次請求就拿到整份清單，沒有這個限制。

### 為什麼會議要留已結束的場次

因為那正是這份資料最有用的地方。這些學會一年只開一到兩次會，官網多半在**開會前一兩個月**
才更新，所以任何時候去看，「下一場」多半還沒公布 —— 過期場次砍光的話，這一頁一年有大半時間
是空的，使用者只會以為壞了。年會與半年會固定落在同一個月份，**上一場的日期就是排下一年的依據**。

前端預設仍然只顯示「即將舉行」；一場都沒有時會直接給一顆「看最近 N 場的日期」按鈕
（不是寫「請按上面的已結束」—— 手機版篩選器預設是收合的，那句話會指向使用者看不到的東西）。

## 網站長怎樣

- 上方是統計（幾場即將舉行、日期範圍、幾個來源、最後更新時間），數字跟著分頁走
- 接著是**置頂的 Guideline 區**（見下一節）—— 常駐，不隨分頁或篩選器改變
- 再來是分頁，分頁下面是六組篩選器（時間／地區／積分／主題／主辦／來源）+ 關鍵字搜尋 + 排序
  - 切到「學會會議」時，**積分軸整列隱藏**、時間軸換成「即將舉行／已結束／全部」
- 清單上方有一顆**訂閱行事曆**的按鈕（見下一節）
- 下面是活動卡片，點標題直接連到原始公告頁，一鍵加進 Google 日曆
- 手機上篩選器預設收起來，第一屏就看得到活動

## 訂閱行事曆（`.ics`）

每個分頁各有一份 iCalendar 訂閱檔，按「訂閱」會用 `webcal://` 交給系統的日曆 App：

| 分頁 | 檔案 | 內容 |
|---|---|---|
| 積分課程 | `data/cme.ics` | 站上「積分課程」分頁的全部場次 |
| 學會會議 | `data/meeting.ics` | 站上「學會會議」分頁的全部場次（含保留的已結束場次） |

**訂閱是選配不是預設**：站主的顧慮是「值班不一定每堂課都上得到，不然就是單純的雜訊」，
所以要不要進日曆由使用者自己按；單筆「加入 Google 日曆」也保留著，兩者互補
（單筆＝我要這一堂；訂閱＝以後都自動給我）。

🔴 **已知取捨，畫面上有寫清楚**：訂閱的粒度是**整個分頁**，
**不跟著地區／積分／時間那些篩選走**。純靜態站沒有後端，不可能為任意篩選組合即時產生 ics。
按鈕旁邊那行說明會寫出實際筆數（「整個分頁的 31 場，不受下面的篩選條件影響」），
因為「篩了南部卻訂到全部」比沒有這個功能更糟。

🔴 **UID 必須跨 build 穩定**，否則訂閱端會把同一場活動當成新事件重複跳出來 ——
這是 ics 最常見也最惱人的坑，而且**不會有任何錯誤訊息**，只有訂閱的人被洗版。
UID 用的識別欄位跟 `build.dedupe()` 判斷「兩筆是不是同一場」**完全相同**
（`kind` + 日期 + `base.norm_title()` 正規化後的標題），刻意不含地點／網址／積分
那些會被官網改來改去的欄位。兩邊共用 `sources/base.norm_title` 同一支函式，
不各留一份 —— 各留一份的話，改了其中一邊就會無聲失準。

其他實作要點（都有 selftest 守著，且經突變測試驗證過測試本身有效）：
- 時間一律台北時區：有起訖時間的單日場次用 `DTSTART;TZID=Asia/Taipei`，
  檔頭帶一段固定 +0800 的 `VTIMEZONE`（台灣沒有日光節約時間）
- 沒寫時間或多日的場次用整天事件，**`DTEND` 是「不含」的所以要 +1 天**（經典 off-by-one）
- 折行以 **octet** 計算而非字元數（中文一個字 3 bytes，用字元數折出來的行會超長，
  嚴格的訂閱端會整份拒收），且不把多位元組字元從中間切開
- 換行是 CRLF（寫檔時 `newline=""`，否則會被再翻譯成 `\r\r\n`）

## Guideline 區（置頂三顆按鍵）

頁面順序是〔標題〕→〔**Guideline 區**〕→〔分頁〕→〔篩選器〕→〔清單〕。這一區跟下面的活動清單
是不同性質的東西，所以視覺上分開、而且**不吃分頁也不吃篩選器**，切到哪一頁都看得到。

| 按鍵 | 連到 | 那個站長什麼樣 | 明年會怎樣 |
|------|------|--------------|-----------|
| TUA guideline | 學會公告頁 | **年度公告型**：每出一版就是一個新網址 | 🔴 網址會換，所以一定要解析 |
| AUA guideline | guidelines 索引頁 | 索引頁固定，頁面上列著各份指引的年度 | 🟢 網址不變，年度會變 |
| EAU guideline | guidelines 索引頁 | 索引頁固定，**頁面上沒有任何版本標示**（年度寫在各疾病內頁正文裡） | 🟢 網址不變 |

**三顆都是動態解析的，沒有寫死任何網址**（`sources/guidelines.py`）。三個站的結構完全不同，
所以是**三支 adapter 共用一個骨架**，不是一套通用爬蟲：

- **TUA**：用學會自己的「顯示全部」參數（`?limit=0`）一次拿完整份公告列表（實測 768 筆），
  找標題／網址符合「TUA治療指引 &lt;年份&gt;」的最新一筆。
  🔴 規則必須**很窄**：這張列表裡有「TUA2025泌尿科治療指引住院醫師**擂台賽**」這種項目，
  年份還比正版新，用寬鬆的「含 guideline 就算」會直接指錯（selftest 有這幾個干擾項的案例）。
- **AUA**：讀索引頁上「`… : AUA Guideline (2026)`」的最大年份當版本標示；網址是索引頁本身。
- **EAU**：檢查索引頁的疾病主題連結還在（實測 21 個），版本年度從一個代表性內頁的正文讀
  （「This 2026 PCa Guidelines …」）。**讀不到年度不算失敗**，按鍵照樣能用，只是不顯示年度。

**每一顆都有 fallback**：解析失敗就退回上次驗證過的網址，絕不讓按鍵變空連結或 404，
並在站上顯示一條「這顆沒能自動確認最新版」的提示、把該次 workflow 標紅。

⏱ **更新頻率有兩層，改 cron 前先看懂**（`.github/workflows/guidelines.yml`）：
**版本更新實質是年頻**（指引一年才出一版），但**連結健康檢查設成月頻**——
「TUA 把公告網址換掉」不挑時間發生，只在每年一月跑的話按鍵可能 404 整整一年沒人知道。
月頻的成本是一年 48 個請求，對三個學會的網站等於沒有負擔。

📌 **2026-08-25 實查**：TUA 官網現行最新就是 **2024 版**（往回掃完整份公告列表確認，
沒有 2025／2026 版）；AUA 最新指引標 **2026**；EAU 現行是 **2026** 版。

卡片上會標的東西：泌尿科點數（還沒核定的標「積分申請中」）、**另外還能拿的其他科積分**、
地區、可不可以線上參加、次專科主題、有沒有錄影。

## 積分是什麼

專科醫師證書更新（展延）要在**六年內累積繼續教育積分 108 點以上**，
出處是學會的[繼續教育積分授予辦法](https://www.tua.org.tw/tua/tw/specialist-of-urology/points)。
同一份辦法也寫了各種取得方式的點數（年會 16 點、半年會 10 點、區域月／季會每次 2 點、
網路繼續教育依影片長度 0.5～2 點且上限 30 點……）。

這個站只做一件事：把「哪一天、在哪裡、有幾點」攤開來讓人挑，**不做點數試算**。
點數的最終認定在學會，站上顯示的是公告當下的值。

### 學會會議（`kind: meeting`）的四個來源

| 學會 | 來源 | 抓哪一頁 | 狀態 |
|------|------|---------|------|
| 台灣泌尿科醫學會（TUA）自己的年會／半年會 | E-School | 首頁列出的**議程總表頁**（`/p/2026_conference` 這類），一場會議一頁 | ✅ 已接 |
| 台灣泌尿內視鏡醫學會（TEA） | <https://www.tea2024.org.tw/> | 「學術活動」清單，每筆是 `YYYY.MM.DD 標題` 加一個連結；地點與時間再從內頁補 | ✅ 已接 |
| 台灣泌尿腫瘤醫學會（TUOA） | <https://tuoa.org.tw/> | 「活動訊息」`info.php` 的卡片列表；地點從 `info_detail.php` 內頁補 | ✅ 已接 |
| 高杏泌尿照護協會（列為 TUA 底下的子項目，來源名「台灣泌尿科醫學會 高杏場次」） | E-School（**它沒有自己的發布管道**） | 列表裡「主辦／協辦欄提到高杏」的場次 | ✅ 已接 |

🔴 **TUA 自己的年會為什麼不從 `conference/list` 撈**（這是最直覺但錯的作法）：
年會在那張表上是**攤成 88 筆個別議程**的（2026 年會 8/22 有 53 筆、8/23 有 35 筆），
每一筆是 Podium／Symposium／Workshop 這種**議程層級**的東西 —— 不能單獨報名、積分欄是空的，
而且「主辦／主持人」欄放的是**座長的姓名**。現行的積分門檻正是靠積分欄空白把這 88 筆擋掉的，
**那一關同時擋著「把個人姓名登在公開網站上」，放寬它等於順手拆掉 PII 防線。**

正確的會議層級來源是 E-School **首頁列出的「議程總表」頁**：一場會議一頁，有名稱、起訖日、地點，
而且首頁直接把它們全部列出來，所以不需要猜網址、也不需要翻議程。
只抓「時間」「地點」兩個帶標籤的欄位，**不碰議程表格**（表格裡全是講者與座長的姓名）。

🔴 **高杏那一條要特別說明，免得日後有人以為是漏做的**：
2026-08-25 查證過搜尋引擎、台灣泌尿科醫學會的「相關網站」清單、以及 Facebook，
**都找不到這個協會的官方網站或粉專**（它是高雄在地的協會，不是全國性學會）。
所以這裡不編一個網址出來，改用它實際留下公開紀錄的地方 —— E-School 的主辦／協辦欄。
站主 2026-08-25 確認：「高杏泌尿照護協會就是在台灣泌尿科協會發文」——
**E-School 實質上就是它的發布管道**，所以這不是「退而求其次」，而是找對了地方。
仍存在的限制：若有「辦了但沒申請泌尿科積分」的場次，那筆就不會出現在 E-School、這裡也抓不到。
卡片上會標「高杏主辦」或「高杏協辦」，因為主辦欄刻意只顯示主辦單位
（協辦多半是藥廠），不標的話會看不懂這場為什麼被歸在這個協會底下。

🔴 **高杏在「來源」篩選器裡掛在 TUA 底下，不是第四個並列學會**（站主 2026-08-25 指定：
「高杏泌尿照護協會應該是歸在台灣泌尿科醫學會下面的子項目」）。實作就是把來源名取成
`台灣泌尿科醫學會 高杏場次`，沿用同一個父層下已有的寫法 `台灣泌尿科醫學會 年會／半年會`，
讓兩條 TUA 會議線在篩選器裡靠字典序自然相鄰 —— **沒有為此新增任何分組 UI，
程式裡也沒有任何父子／前綴比對邏輯**（來源軸就是 `Object.keys(...).sort()` 平鋪）。
「子項目」是命名前綴造成的視覺效果，不是一個機制；真要層級 UI 得另外做 `parent` 欄位。
（是**兩條**不是三條：積分課程那條 `台灣泌尿科醫學會` 是 `kind=cme`，在另一個分頁。）
這樣寫也符合事實：高杏的場次本來就是登在 TUA 的 E-School 列表上。
⚠️ 不可以把它取成跟其他來源完全相同的名字：`scripts/build.py` 的 `per_source` 以來源名當 key，
**同名會互相覆蓋**（帳面只剩一個，`kind` 還會變成後跑那支的）。父子關係走命名前綴，不走共用同名。

⚠️ **官網的原始資料本身就有打錯的地方**，那是來源的原文不是解析壞掉，照實呈現不要「修正」：
TEA 有一筆標題寫成「2025年健康台灣 Health Taiw」（後面真的沒了），
E-School 有一筆寫成「…冬季研習會aiwan Hernia Society…」（少了一個 T）。

### 為什麼「積分欄有沒有寫泌尿科」是收錄門檻

E-School 的列表同時裝了兩種東西：**可以單獨報名的課程**，和**年會的議程項目**。
兩者長得很像，但議程項目的積分欄是空的，而「主辦／主持人」欄放的是主持人的姓名。

所以 `sources/base.py` 的 `has_urology_credits()` 就是那道門：積分欄有提到「泌尿科」才收。
一條規則同時解決三件事 —— 擋掉 88 筆議程、擋掉他科課程、也避免把個人姓名當主辦單位登在公開網站上。

「泌尿科(申請中)」**要收**：學會的區域月會半年前就掛上來、點數還沒核，
而那正是需要提前排時間的課。這種場次會標成「積分申請中」，不會被當成 0 點。

## 怎麼加新來源

**一個來源 = 一支獨立檔案**，加來源不用動前端也不用動排程。

1. 在 `sources/` 底下新增一支 `xxx.py`，裡面要有：
   - `NAME`：學會名稱（會顯示在網站的來源篩選器上）
   - `KIND`：`KIND_CME`（積分課程）或 `KIND_MEETING`（學會開會時間），沒寫就當積分課程
   - `fetch()`：回傳 `list[Event]`
2. 把它加進 `scripts/build.py` 最上面的 `SOURCES` 清單
3. 跑 `python3 scripts/build.py --dry-run` 確認抓得到

新來源如果是從官網的自由文字裡抽欄位（不像 E-School 有獨立的聯絡人欄可以整欄不收），
抽出來的字串一律先過 `base.scrub_contacts()` 再放進 `Event` —— 學會官網很常把承辦人的
電話與信箱寫在地點同一段。`scripts/pii-scan.sh` 是最後一道閘門，不是第一道。

`Event` 的欄位、地區判定、積分解析、分類判定全部在 `sources/base.py`，新來源直接拿來用：

```python
from .base import Event, get, parse_date, parse_credits, detect_region, detect_categories
```

## 動手改之前要知道的三件事

1. **時間基準一律台灣（+08:00），不看機器時區**。`sources/base.py` 的 `TAIPEI` / `today_taipei()`
   是唯一權威。這不是潔癖：Actions runner 跑在 UTC，排程台灣 06:00 ＝ UTC 前一天 22:00，
   用 runner 日期判斷「過期」會整整差一天、把當天的課砍掉。前端 `todayISO()` 同理。
2. **積分只從「會議積分」欄的「泌尿科」那一段抓，不從標題猜**。同一格裡常常有別科的點數
   （`泌尿科(1.5點) ,婦產科,內科,家醫科3點`），在整串裡找數字會抓到 3 點。
3. **日期欄只有 MM-DD，年份來自 `display_date` 這個查詢參數**，不在頁面文字裡。
   跨年的多日活動由 `eschool._resolve_date()` 補正。
4. **兩種 `kind` 的保留下界不同**，用的是同一支 `base.cutoff_iso(kind)`。
   來源層若要自己過濾過期資料，一定要用它而不是 `today_iso()` —— 用錯的話該來源
   會跟彙整層對不上，而且看起來一切正常，只是資料少了一截。

改完請跑 `python3 scripts/selftest.py` —— 上面四件事都在裡面有測試案例。

### 個資閘門的設計（`scripts/pii-scan.sh`）

這支腳本自己也會被公開，所以**裡面不寫任何人的真名或信箱** ——
「掃描規則」本身就是一條外洩管道，而且它會通過自己的檢查。
因此它只掃**形狀**：信箱樣式、家目錄絕對路徑、常見 API 金鑰與 token 前綴、授權標頭、身分證字號樣式、電話。
實際的樣式清單直接看 `scripts/pii-scan.sh` 開頭的 `PII_PATTERNS`（**文件裡刻意不抄那些字面值** ——
寫進 README 會讓 README 自己被閘門判成命中）。

針對特定人名的規則放在 `.pii-local`（已列進 `.gitignore`，一行一個 regex）。
本機跑會自動載入並提示；CI 上沒有那個檔，就只跑形狀規則。
⚠️ 代價是**人名類個資 CI 擋不住**，上架或大改動前請務必本機跑一次 `--all`。

## 來源掛掉會怎樣

不會整包壞掉，也不會把網站洗成 0 筆。三層防線，針對的是同一種失敗：**資料默默停止更新，畫面上卻看不出來**。

1. **抓到 0 筆一律當失敗**（不管來源有沒有丟例外）。來源改版時最常見的樣子是
   HTTP 200、HTML 解析成功、只是選擇器對不上 —— 沒有任何例外可抓。
2. **失敗時保留既有活動資料，但把錯誤訊息換成這次的**，並在網站頂部跳一條
   「顯示的是 ⋯⋯ 的舊資料」。`updated_at` 刻意不更新 —— 那個欄位的意思是「資料有多新」。
3. **解析層自己會喊**：表格不見、或「有列卻一筆都解不出來」都會發 warning 寫進
   `errors` 欄位。部分來源失敗時其他來源照常更新。
